# Sparse 镜像合同

[项目](../README.md) · [验证](verification-ledger.md)

## 一个逻辑地址空间，四种表示

Android sparse-v1 描述连续逻辑块。存储偏移定位编码文件字节，逻辑偏移定位展开镜像；两者不能互换。

| Chunk | 存储 payload | 逻辑效果 |
| --- | --- | --- |
| RAW | 声明的块字节 | 以借用输入切片交付数据 |
| FILL | 一个四字节模式 | 在声明块内重复模式 |
| DONT_CARE | 无 | 为逻辑范围发出 `SkipData` |
| CRC32 | 一个四字节校验和 | 检查累计逻辑前缀，不贡献块 |

CRC 计算将跳过字节按零处理；多个 CRC chunk 之间不重置 CRC 状态。启用校验时，结束阶段验证非零镜像头校验和。

`SkipData` 与 FILL(0) 不同。新 raw 文件展开器会将跳过范围实体化为零，但向已有目标应用事件的调用者必须保留跳过决定。writer 只为显式 `Hole` pieces 生成 DONT_CARE，零填充输入块仍是数据。

## 增量读取与失败

decoder 保持固定 28 字节前缀暂存，跳过扩展头字节，借用 RAW payload 切片。调用者须在回调内消费或复制借用数据。相同字节以不同分段输入时，chunk 元数据及拼接逻辑输出保持一致，RAW 回调边界可能变化。

接受 major 1 和兼容 minor，文件头至少 28 字节、chunk 头至少 12 字节，块大小为正且能被四整除。拒绝空镜像、未知 chunk、长度不一致、chunk/块总量不匹配、算术溢出、截断和尾随字节。错误附带存储输入偏移。取消、回调错误及重入会使对应会话失效；重试时创建新会话。

decoder 刻意比固定 AOSP importer 更严格：检查非零头 CRC、CRC chunk 的声明块数必须为零、拒绝尾随字节。对照时记录这些策略差异，不能将更严格的拒绝视为互操作验证结果。

## 独立预算

| 预算 | 核心默认值 | 主机行为 |
| --- | --- | --- |
| 展开字节 | 64 GiB | inspect/validate 使用该上限；expand 接受 `--max-output` |
| CRC 计算量 | 256 MiB | 计算前检查，独立于展开量 |
| Chunk 数量 | 1,000,000 | 检查器/校验器最多保留 10,000 个 |
| 便捷打包 | 受 API 限额控制 | CLI raw 输入和序列化结果各不超过 64 MiB |

计数使用检查溢出的算术。检查巨大空洞不分配其逻辑内容；重复计算 CRC 仍需与展开字节数成比例的工作，因此启用 CRC 可能拒绝不启用时可检查的镜像。Node 每次读取 1 MiB，展开 sink 单次输出最多 64 KiB。

## 写出已知 pieces

`write_sparse` 首次调用输出回调前，预检所有已知 pieces 及其大小。`Data`、`Fill`、`Hole` 保留各自含义。序列化大小与累计块数必须能放入格式字段；非完整尾块直接拒绝，不隐式填充或截断。

`encode`、`pack` 是有界 Bytes 便捷 API，不代表无限制单遍 raw 输入打包或巨大 RAW chunk 拆分。文件系统发布及主机错误留在纯核心之外；CLI 只在转换成功后发布临时输出。

## 范围边界

库处理 sparse-v1 表示、校验、转换，不实现 resparse、fastboot、USB、刷机、设备写入、ext4/EROFS、dynamic-super、boot image 或任意压缩封装。wasm-gc 核心测试不代表 native 文件系统适配完成。浏览器检查器是本地演示。
